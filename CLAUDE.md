# Cache Play — Blender add-on

Project folder: `Z:\DEVELOPMENT NEW STYLE\DEV AUTOMATION\Blender Addon Dev\Cache Play\`
Owner: Albert (Zeus Animation Studio). Uses After Effects and Blender daily; explain technical terms in plain words.

## Goal
Give Blender an After Effects–style cached preview. Blender's viewport rebuilds the scene every frame during playback, so frame times are uneven and motion judders even with Frame Dropping on. Cache Play renders each frame of the viewport once, stores the picture, then plays the pictures back on its own fixed clock at exactly the scene fps.

## Decisions made so far
- **Core trick:** during cached playback, do NOT change `scene.frame_current` (that triggers depsgraph evaluation and brings the stutter back). Keep an internal playhead, draw the cached image over the viewport with a `SpaceView3D` `POST_PIXEL` draw handler, and drive timing with a modal operator + timer. Draw our own playhead and cache bar on the timeline.
- **Capture:** `gpu.types.GPUOffScreen` + `draw_view3d()` for each frame. Viewport shading only (Solid, Material Preview, EEVEE). Cycles is out of scope.
- **Preview size presets:** Full, Half, Third, Quarter. Default Third (v0.2.21).
  - Full = the render resolution, **capped at 1080p** (fit inside 1920×1080, keep aspect; 4K project → 1920×1080; vertical → max 1080×1920).
  - Half / Third / Quarter are divisions of that capped Full size (16:9: 960×540, 640×360, 480×270).
- **Two-tier storage (like AE 25.2+ "Preview from Disk Cache"):**
  - Disk is the real store: every frame written as raw bytes, one file per frame, in a user-chosen cache folder with a size limit and least-recently-used eviction.
  - RAM is a read-ahead ring buffer. A background thread reads frames ahead of the playhead (file reads release the GIL; `numpy.memmap` is an option). Main thread uploads to a GPU texture and draws.
  - Timeline bar colors: green = in RAM, blue = on disk, empty = needs re-render.
- **Invalidation:** `depsgraph_update_post` + `depsgraph.updates`. Simple mode: any edit clears all. Smart mode: edited F-curve key range only. Shading/size changes clear everything (the view itself no longer matters: camera only).
- **Idle caching:** `bpy.app.timers` fills dirty frames in small chunks after a few seconds of no input; stop as soon as the user interacts (like AE "Cache Frames When Idle"). Cache Only caches from the playhead to the range end, then the frames before it (v0.2.22). Cache & Play (v0.2.25, reworked after 0.3.0: `_play_through`/`_fill_gaps`, `_live_tick`) plays the whole range from the playhead (`player.state.frames` = range) and caches while playing, one frame per timer tick (`_capture_live`: `frame_set` + `Capturer.capture()` + put, under `state.capturing` so it is not an edit; no Fast GPU overlap here). It follows `scene.sync_mode`: NONE (Play Every Frame) stops the clock at the first uncached frame passed (`_next_gap`) and re-anchors `t0` after caching it, so every frame shows in order; FRAME_DROP and AUDIO_SYNC (`_drop_frames`) keep the clock, caching only the frame the clock lands on, so later loops fill the skipped ones. `state.caching` adds "caching" to the status label. A full cache turns gap filling off (cached-only playback). Stopping a fill (Esc/Space) leaves the scene on `_last_stored` if Move Playhead on Stop (not in Cache Mode); `_end_fill(context, frame)`; `_finish` restores `_orig_frame` otherwise. Test: `tests/test_play_through.py`.
- **Persistence across sessions ("name tags"):** key = .blend path + frame + camera/view matrix + resolution preset + shading mode + an edit counter stored in the .blend + mtimes of linked libraries. Mismatch → re-render. Always provide a Clear Cache button. (Blender removed the VSE disk cache in 4.5 because of stale frames — this keying is how we avoid that.)
- **Kept caches** (2026-10-28, `store.persist_tag`, `disk.py`): saved .blend files cache into `<cache folder>/caches/<sha1 of tag>/` (frame files + `info.json`; `.lock` held while in use; `disk.FolderLock`/`in_use`). Tag = path, scene, capture key, `scene.cache_play.edit_id` (StringProperty saved in the .blend, new `uuid4` on every real edit in `_on_depsgraph_update`, even with nothing cached), `_deps_signature()` (path + mtime of libraries, images, cache files, volumes), Blender version, `disk.FORMAT`. A folder is reusable if made by this process (`disk.SESSION_ID`) or if `info.blend_mtime` equals the .blend's mtime noted at load/save (`_disk_state`, `_note_disk_state` in load_post/save_post/`_startup`); otherwise its frames are deleted on open. `blend_mtime` is written when the tag's edit id equals the one on disk (`at_disk_state`), and `FrameCache.saved()` (save_post) updates it, plus path after Save As. `adopt_kept_cache()` (timer 0.1 s after load_post, or on register) scans `info.json`s for the window scene and adopts the newest match: `FrameCache.adopt` sets key from JSON (`_tupled`). It also seeds `_last_frame`, else the first edit after opening looked like a frame change and was ignored. `clear(delete=False)` (edits, load_pre, shutdown, other key) keeps a kept folder; `clear()` (Clear button) trashes it; session folders (unsaved files) always go. Disk limit = own + other kept caches (`_measure_others`); `has_room`/`put` evict the least recently used others first (`_evict_others`, rename to `.trash_*`, writer deletes). `cacheplay.clear_all` + usage line in prefs (`ui._kept_usage`, refreshed every 5 s). Test: `bash tests/run_persist.sh <blender.exe> <work dir>`.
- **Audio:** play scene sound via the `aud` module, synced to our clock.

- **Cache Mode** (added 2026-10-23, v0.2.1; reuse rule v0.2.2): toggle (`cacheplay.cache_mode`, panel + `DOPESHEET_HT_header`) that runs the playback modal paused with `cache_mode=True`. Left-drag anywhere in a Timeline, or in the scrub band of a Dope Sheet / Graph Editor / NLA, moves only the cache playhead (the Drivers editor is skipped: its x axis is not frames). The cache bar and labelled cache playhead draw in all of these editors (v0.2.3); Space/arrows play and step; every other event passes through to Blender. Never changes `scene.frame_current` and never clears or re-caches: if any frame of the range is cached (even from another viewport or settings) it reviews that; it fills only an empty cache. From a non-3D editor it uses the viewport the cache was made from (`frame_cache.area_ptr`). Exits on Esc, toggle (`exit_requested` flag), or when an edit bumps the cache generation. Because of this, `player.busy()` no longer counts active playback: edits during playback/Cache Mode must invalidate.
- **Camera only** (v0.2.7): every capture goes through `scene.camera` (`Capturer.mode` is always CAMERA; the old free-view mode is gone). Cache & Play / Cache Only / Cache Mode switch the viewport to camera view first (`capture.ensure_camera_view`); no camera = error. The viewport supplies only shading/overlays, so orbiting never invalidates; idle caching works from any view without changing it. The overlay sits on the camera frame, or centred when the viewport is out of camera view. Cache Mode (v0.2.19) saves the view before switching (`capture.save_view`: perspective, location, rotation, distance, camera zoom/offset) and `_finish` restores it on any exit if the area still exists; Cache & Play does not.
- **UI** (v0.2.8): main controls are a horizontal bar in the Timeline header right after the Playback popover (v0.2.9: `bl_ui.space_dopesheet.playback_controls` is wrapped and given a stand-in layout whose `popover(panel="TIME_PT_playback")` also draws the bar; restored on unregister; if that popover is never drawn, the `DOPESHEET_HT_header` append draws the bar at the right end instead) (other Dope Sheet modes: Cache Mode toggle only), with a header popover `DOPESHEET_PT_cache_play` for Cache Only, status, details and statistics. Below `ui.TIMELINE_BAR_WIDE` (1750 px × UI scale) the two main buttons go icon-only; Blender's own Timeline header needs ~1100 px. The 3D View sidebar panel stays as a second place with the same controls.
- **Viewport toolbar + shortcuts** (v0.2.12, default UI): `toolbar.py` gizmo group `VIEW3D_GGT_cache_play` draws a pill fixed at the bottom centre of each 3D Viewport (no dragging): icon-only GIZMO_GT_button_2d per action (`draw_options` empty, alpha 1, because button_2d fades its icon with its backdrop alpha; `scale_basis` in unscaled px since Blender multiplies by the UI scale) plus custom `CACHEPLAY_GT_pill`, created last because a group draws gizmos newest first, which draws the pill, hover/on circles, cached count and a chevron. Clicking the chevron toggles pref `toolbar_collapsed`; a custom gizmo's click must return RUNNING_MODAL from invoke (FINISHED is ignored). Responsive (`toolbar.Geometry`): full pill, then no count, then only ▶ and 🎞, based on region width. No modal operator, so autosave keeps working. Pref `toolbar` = VIEWPORT / TIMELINE / BOTH decides whether the Timeline bar shows. Shortcuts F5 (Cache & Play), F6 (Cache Mode) and Ctrl+F5 (Clear, v0.2.20) in the addon Window keymap (`ops.SHORTCUTS`: idname, key, modifier kwargs); F5–F8 plain and with Ctrl, Alt, Ctrl+Shift, Ctrl+Alt, Shift+Alt are unused in 5.1/5.2 default keymaps (only Shift+F5–F8, checked 2026-10-27). Scanning keymaps needs a real window: in `-b` the default keyconfig is empty.
- **Spacebar option** (v0.2.23): pref `space_plays_cache` (default off). `CACHEPLAY_OT_space_play` (INTERNAL) is bound to SPACE in an addon "Frames" keymap, which Blender lists before its own `screen.animation_play`; its poll needs the pref, `preview_size == QUARTER`, a scene camera, no Cache Play or Blender playback running and a 3D Viewport, and a failed poll lets Space fall through to Blender's Play. Invoke calls `cacheplay.preview(space_toggle=True)`: then Space (not is_repeat) stops caching like Esc and stops playback like any other key (v0.2.24), instead of pausing; hint texts say so. Poll rules tested; the real key press needs a hand check (event_simulate never reaches keymaps).
- **Toolbar cursor** (v0.2.18): `GIZMO_GT_button_2d` has a C `cursor_get` that forces the arrow cursor while hovered (`WM_gizmomap_cursor_set`). Python gizmo types have no `cursor_get`, so they leave the cursor alone. The button_2d gizmos now only draw icons (`hide_select = True`); an invisible `CACHEPLAY_GT_hit` gizmo per button does the hit test (circle) and carries `target_set_operator` (Blender then runs the operator like a button_2d click, modal operators included). Hover circles use `hit.is_highlight`; operator tooltips still show (verified).
- **Export** (v0.2.16, `export.py`, `cacheplay.export`): cached frames → PNGs in a temp folder → one image strip in a temporary scene → `render.render(animation=True, scene=...)` to MP4/H.264 (`image_settings.media_type='VIDEO'` in 5.x, view transform Standard so colours pass through). Uncached frames repeat the previous cached one. No audio. Pill button after the count; also in the panels and Timeline bar. Opening/closing a window (the file browser) makes the depsgraph re-sync every visible object as shading-only; `store._is_visibility_resync` and `_windows_changed` ignore that, or cancelling the dialog cleared the cache.
- **Settings button** (v0.2.16): `CACHEPLAY_OT_settings` goes modal on press and calls `wm.call_panel(keep_open=True)` on release, so a plain click opens the drop-down. Panel layout (v0.2.16): shared blocks `_draw_actions` (Cache Only | Export), `_draw_settings`, `_draw_status` (box, Clear beside the count; idle status only while frames are missing), `_value_rows` for details/stats; the drop-downs fold Details/Statistics with `layout.panel()`.
- **Faster filling** (v0.2.17, measured with `tests/profile_fill.py`): `Capturer.draw()` / `read()` are split and `ops._fill_step` overlaps them (frame_set N+1, then read N, then draw N+1; `_collect()` stores the drawn frame, also on Esc; pref `fast_caching` (Fast GPU Caching, default OFF since v0.2.21 by the owner's choice) switches overlap and GPU packing on: `Capturer(gpu_pack=...)`). `capture._stamp_alpha()` draws a full-screen quad with colour mask alpha-only and alpha 0x40/255, so the RGBA8 readback already is the `store.pack_pixels` format; `read()` returns `np.frombuffer(buffer, float32)` and `FrameCache.put()` takes packed arrays (bit-exact on Vulkan and OpenGL). `FILL_SLICE` 0.25 s (fewer window redraws). Vulkan Cache Only on the 55 ms/frame scene: ~127 → ~86–96 ms/frame. Idle caching still uses `capture()` (draw + read, one frame per step).
- **Cached picture is drawn in POST_VIEW** (pixel-space matrices, depth off) so 2D gizmos (toolbar, navigation) draw on top; text stays in POST_PIXEL: since v0.2.14 a compact status label in the pill style, centred just above the toolbar pill (`draw._draw_hud`, shortens on narrow viewports). `toolbar.Geometry()` sets its own blf size, so set the label's size again right before drawing. Never bind an offscreen inside POST_VIEW (it breaks the viewport redraw): `display.prepare()` unpacks the frame in the operator before `tag_redraw`, the draw callback only reads `display.texture()`.
- **zeploy usage counts** (v0.2.19): `zeploy_usage.py` is the studio deployment tool's helper, copied unchanged from the zeploy repo (`examples/usage/`); never edit it here. `__init__.usage` (id `cache_play`, version read from the manifest) counts `cache and play` / `cache only` / `cache mode` in `CACHEPLAY_OT_preview.invoke` (any result but CANCELLED; invoke wraps `_start`), `clear cache` and `export` with `@usage.track` on `execute`, and errors on a fill or export failure. Idle caching is never counted. Writes only where `%LOCALAPPDATA%\zeploy` exists; tests can point `LOCALAPPDATA` at a temp folder.

## Build plan
1. **v1** — RAM only: fill a range, play back at locked fps from memory. First thing to validate: is drawing a cached texture on our own clock truly smooth, without Blender's own redraws interfering? Test on a heavy scene. **Done 2026-10-23; validated** — 0 dropped frames and ≤1 ms jitter on a 55 ms/frame scene in 5.1 (OpenGL) and 5.2 (OpenGL + Vulkan). Results in `README.md`.
2. **v2** — Disk store + read-ahead streaming, timeline cache bar, idle caching. **Done 2026-10-23.** Disk = one raw packed file per frame in `<cache folder>/session_<pid>_<time>/<generation>/`, written by a writer thread; RAM = LRU dict, reader thread loads the playback window ahead of the playhead. Disk limit stops caching (no LRU eviction yet). Session folders are deleted on clear/exit; crashed sessions' folders are purged via a file lock. VRAM storage option from v1 dropped (no measurable benefit). Streaming Full 1080p with RAM holding 32/120 frames: 0 dropped, 0 late reads.
3. **v3** — Persistence across sessions (name tags), smart per-range invalidation, LRU eviction across caches when the disk limit is hit, Clear Cache. **Persistence, LRU eviction and Clear All done 2026-10-28** (see Kept caches above); smart per-range invalidation still to do.

## Known limits
- Filling the cache runs on Blender's main thread → do it in chunks with a progress bar.
- Memory: Full (1080p RGBA8) ≈ 8.3 MB/frame ≈ 2 GB per 10 s @ 24 fps; disk read ≈ 200 MB/s. Consider RGB (−25%) and optional lossless lz4/zstd via a bundled wheel.
- Simulations depend on earlier frames: bake first, or invalidate forward from the edit.
- GPU→CPU readback is needed for disk storage.
- Idle caching runs while Cache Mode is open and paused (new frames join the scrub list via `frame_cache.added`), not during cached playback. `idle.status` explains what it is doing; the panel shows it.
- An idle-caching step evaluates the scene twice (jump to the frame and back): ~150 ms on the 55 ms/frame test scene.

## Verified API facts (Blender 5.1 / 5.2)
- `GPUOffScreen.draw_view3d(scene, view_layer, view3d, region, view_matrix, projection_matrix, *, do_color_management, draw_background)` works from a modal operator, gives converged anti-aliasing, and **includes viewport overlays** if they are on.
- `gpu.types.GPUTexture(..., data=buf)` accepts **only FLOAT buffers**. Workaround (`store.pack_pixels`, `display.py`): pack R,G,B bytes into the low 24 bits of a float32 with top bits `0x40000000` (always a normal float), upload as `R32F`, unpack with a small shader. Bit-exact, 4 bytes/pixel, verified on OpenGL and Vulkan.
- `gpu.types.Buffer` supports the buffer protocol (`numpy.frombuffer` is zero-copy, `memoryview` is writable).
- Idle detection: Blender's Python API has no "last input" signal, and a Window-keymap `MOUSEMOVE` hook could not be verified (under `--enable-event-simulate` even built-in shortcuts did not fire from timer-driven `event_simulate`). Never use a permanently running modal operator for this: Blender skips autosave while any modal operator runs. Used instead (v0.2.5, After Effects-like): on Windows, only while Blender is the foreground window (`GetForegroundWindow` pid == own pid), a held/pressed key or mouse button (`GetAsyncKeyState` & 0x8001) or input without cursor movement (`GetLastInputInfo` changed, `GetCursorPos` same: key tap, wheel) counts as working; plain mouse movement and other programs do not. macOS (untested): any input in the last 0.5 s. Plus depsgraph/frame/view changes everywhere. v0.2.13: the probe returns a set of activity kinds (KEYS, MOUSE, OTHER_APPS; EDITS comes from handlers and view checks) and only kinds ticked in pref `idle_activity` (ENUM_FLAG, default KEYS + EDITS + MOUSE since v0.2.15; OTHER_APPS off) reset the idle clock. Tests replace `idle._interaction_probe` with a function returning such a set. Default idle delay 3 s.
- `Window.modal_operators` lists running modal operators; some add-ons keep one forever (here `PPF_OT_frame_pump`).
- Background threads run fine in Blender (file I/O releases the GIL). Keep `bpy`/`gpu` calls on the main thread; threads only touch files and numpy arrays.
- GLSL: `packed` is a reserved word on OpenGL (Vulkan accepts it). Test shaders on both backends; factory startup defaults to OpenGL, this machine's prefs use Vulkan.
- Frame changes (`screen.frame_offset`, scrubbing, `frame_current =`) fire `depsgraph_update_post` with transform updates, sometimes **before** `frame_change_pre`. Invalidation ignores updates where the frame moved since the last handler call, plus 50 ms after `frame_change_post`.
- Selection changes report only a Scene update.
- Windows main-loop timers tick about every 1 ms during playback; idle loop sleeps 5 ms.
